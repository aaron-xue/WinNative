# Box64 环境变量说明

> 以下环境变量定义来自 `box64_env_vars.json`，用于控制 Box64（x86_64 到 ARM64 动态重编译器）的运行时行为。

---

## Dynarec 核心设置

### BOX64_DYNAREC
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用或禁用 Box64 的动态重编译器（Dynarec）。
- `0`：禁用 Dynarec，使用解释器模式（极慢）
- `1`：启用 Dynarec（正常运行）

---

### BOX64_DYNAREC_SAFEFLAGS
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `1` |
| 可选值 | `0`, `1`, `2` |

控制 Dynarec 对 CPU 标志位（Flags）的安全处理级别：
- `0`：不进行安全检查（最快，但可能导致某些程序崩溃）
- `1`：进行基本安全检查（推荐）
- `2`：进行严格安全检查（较慢，兼容性最高）

---

### BOX64_DYNAREC_FASTNAN
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用快速 NaN（Not a Number）处理。Arm64 和 x86_64 对 NaN 的处理方式不同，启用此选项可加速浮点运算，但可能会影响与 NaN 相关的某些边缘情况。

---

### BOX64_DYNAREC_FASTROUND
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `1` |
| 可选值 | `0`, `1`, `2` |

控制浮点舍入模式的模拟精度：
- `0`：精确模拟 x86 舍入行为（较慢）
- `1`：快速舍入（推荐）
- `2`：最快舍入（可能不精确）

---

### BOX64_DYNAREC_X87DOUBLE
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

控制 x87 FPU 指令的模拟方式：
- `0`：使用 float 类型模拟（默认）
- `1`：使用 double 类型模拟（更高精度但较慢）
- `2`：混合模式

---

### BOX64_DYNAREC_BIGBLOCK
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `2` |
| 可选值 | `0`, `1`, `2`, `3` |

控制 Dynarec 构建的代码块（Block）大小：
- `0`：最小块（兼容性最高，性能最低）
- `1`：中等大小
- `2`：较大块（推荐，平衡性能与兼容性）
- `3`：最大块（最高性能，可能降低兼容性）

---

### BOX64_DYNAREC_STRONGMEM
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2`, `3`, `4` |

控制内存模型的强一致性级别。x86 具有强内存序模型（TSO），而 Arm 是弱内存序模型：
- `0`：不添加内存屏障（最快，但部分多线程程序可能出问题）
- `1`~`4`：逐级加强内存屏障，值越大越严格

---

### BOX64_DYNAREC_FORWARD
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `128` |
| 可选值 | `0`, `128`, `256`, `512`, `1024` |

设置 Dynarec 前向跳转的最大指令数。超出此范围的跳转将结束当前代码块。

---

### BOX64_DYNAREC_CALLRET
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

控制函数调用（Call）和返回（Ret）指令的处理优化：
- `0`：不优化
- `1`：基本优化
- `2`：激进优化

---

### BOX64_DYNAREC_SEP
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `1` |
| 可选值 | `0`, `1`, `2` |

控制代码段与数据段的分离策略。影响 Dynarec 如何处理自修改代码（Self-Modifying Code）。

---

### BOX64_DYNAREC_WAIT
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

在 Dynarec 中启用 Wait 指令的模拟。某些使用 x87 FPU 的老游戏需要此选项才能正常运行。

---

### BOX64_DYNAREC_WEAKBARRIER
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `1` |
| 可选值 | `0`, `1`, `2` |

控制使用弱内存屏障的级别。与 `STRONGMEM` 配合使用，影响内存操作的重排序。

---

### BOX64_DYNAREC_ALIGNED_ATOMICS
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

强制原子操作使用对齐的内存地址。某些程序依赖对齐的原子操作，启用后可以提高兼容性但略微降低性能。

---

### BOX64_DYNAREC_DF
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

控制是否模拟 x86 的方向标志位（Direction Flag）。涉及字符串操作指令（如 `movs`、`stos` 等）的正确模拟。

---

### BOX64_DYNAREC_DIRTY
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

控制 Dynarec 对"脏"寄存器（被修改过的寄存器）的处理策略：
- `0`：不清洗脏寄存器（默认）
- `1`：部分清洗
- `2`：完全清洗（最安全但最慢）

---

### BOX64_DYNAREC_NATIVEFLAGS
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

使用原生 ARM64 CPU 标志位来模拟 x86 标志位。启用后可大幅提升性能，但可能在某些边缘情况下导致不兼容。

---

### BOX64_DYNAREC_PAUSE
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2`, `3` |

控制 Dynarec 中 `PAUSE` 指令的模拟行为（x86 `pause` 指令用于自旋锁优化）：
- `0`：不模拟（默认）
- `1`~`3`：逐级增加暂停时间

---

### BOX64_DYNAREC_NOARCH
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

禁用特定 ARM 架构扩展在 Dynarec 中的使用：
- `0`：允许使用所有架构扩展（默认）
- `1`：部分限制
- `2`：严格限制

---

### BOX64_DYNAREC_VOLATILE_METADATA
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用易失性元数据处理。影响 Dynarec 如何追踪函数调用间的寄存器状态，启用后可提升性能。

---

## Dynarec 缓存

### BOX64_DYNACACHE
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

控制 Dynarec 的代码缓存大小：
- `0`：默认缓存大小
- `1`：扩大缓存
- `2`：最大缓存（适合大型程序）

---

## 指令集 / CPU 特性模拟

### BOX64_AVX
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1`, `2` |

控制 AVX（Advanced Vector Extensions）指令集的模拟级别：
- `0`：不支持 AVX（默认，兼容性最高）
- `1`：支持 AVX
- `2`：支持 AVX2

> 启用 AVX 会显著增加 CPU 开销，仅在程序明确需要 AVX 时才开启。

---

### BOX64_AES
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用 AES-NI 指令集的模拟。用于加密/解密加速，大多数现代程序依赖此功能。

---

### BOX64_PCLMULQDQ
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用 PCLMULQDQ 指令的模拟。用于无进位乘法，常见于加密算法和哈希计算。

---

### BOX64_SHAEXT
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用 SHA 扩展指令的模拟。用于 SHA-1/SHA-256 哈希加速。

---

### BOX64_SSE42
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用 SSE4.2 指令集的模拟。许多较新的程序/游戏需要 SSE4.2 支持。

---

### BOX64_SSE_FLUSHTO0
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

启用非规格化浮点数清零（Flush to Zero）模式。将极小的浮点数（非规格化数）强制清零，可提升某些程序的浮点运算性能。

---

### BOX64_X87_NO80BITS
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

禁用 x87 FPU 的 80 位扩展精度。x87 内部使用 80 位精度，而 ARM64 只支持 64 位。启用后使用 64 位模拟 80 位，精度略低但速度更快。

---

## CPU 类型与核心数

### BOX64_CPUTYPE
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

控制向应用程序报告的 CPU 类型：
- `0`：报告为 ARM 兼容 CPU
- `1`：报告为 x86 兼容 CPU

---

### BOX64_MAXCPU
| 属性 | 值 |
|------|-----|
| 类型 | 选择 |
| 默认值 | `0` |
| 可选值 | `0`, `4`, `8`, `16`, `32`, `64` |

限制向 Windows 程序报告的 CPU 核心数：
- `0`：使用实际 CPU 核心数
- `4` ~ `64`：报告指定数量的核心

> 某些老旧游戏在多核 CPU 上会出现问题，降低报告的 CPU 核心数可能解决兼容性问题。

---

## 特定引擎兼容性

### BOX64_UNITYPLAYER
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

UnityPlayer 兼容模式。启用后可修复一些 Unity 引擎游戏在 Box64 下的特定问题。

---

### BOX64_UNITY
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `0` |
| 可选值 | `0`, `1` |

通用 Unity 引擎兼容模式。与 `BOX64_UNITYPLAYER` 配合使用，覆盖更广泛的 Unity 引擎游戏。

---

## 内存管理

### BOX64_MMAP32
| 属性 | 值 |
|------|-----|
| 类型 | 开关 |
| 默认值 | `1` |
| 可选值 | `0`, `1` |

启用 32 位内存映射支持。允许在低 4GB 地址空间进行内存映射，这对于某些需要 32 位指针的 64 位程序至关重要。
